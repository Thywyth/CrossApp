## 1. Предметна область (Domain)

- **Назва:** Склад (Warehouse Management System — продовольчі товари).
- **Призначення:** Облік надходження, руху та зберігання партій продовольчої продукції, контроль залишків і термінів придатності між різними складськими локаціями.
- **Ключові сутності:**
  * `Product` — доменна сутність номенклатури товарів із захищеними інваріантами залишку та бізнес-операціями.
  * `StockBatch` — партія продукції з фіксацією дати надходження, терміну придатності та собівартості.
  * `Warehouse` — складське приміщення чи зона зберігання (наприклад, сухий склад, холодильний термінал).
  * `Movement` — транзакція переміщення партій товарів між складами, оприбуткування або списання.

## 2. Архітектура та структура рішення (Solution)

Проєкт організовано за принципом відокремлення інтерфейсу користувача від ядра бізнес-логіки:

```text
CrossApp/
├── CrossApp.slnx            # Файл рішення нового формату (.slnx)
├── README.md                # Інженерна документація проєкту
├── .gitignore               # Правила виключення артефактів збірки (bin/, obj/, publish/)
├── data/                    # Тестові набори даних для імпорту
│   ├── sample.csv           # Базовий CSV-файл (10+ валідних записів, 3 тестові дефекти)
│   ├── sample.json          # Тестовий JSON-файл товарів
│   └── mixed.csv            # Поліморфний CSV з префіксами (товари 'P' та склади 'W')
└── src/
    ├── Core/                # Бібліотека класів (.NET Class Library)
    │   ├── Core.csproj      # Конфігурація (multi-targeting: net8.0;net10.0)
    │   ├── EnvironmentInfo.cs # Збір системних параметрів середовища
    │   │
    │   ├── Domain/          # Доменна модель із поведінкою та інкапсуляцією (ЛР4)
    │   │   └── Product.cs   # Багата доменна сутність (Rich Domain Model)
    │   │
    │   ├── Dto/             # Незмінні моделі передачі даних (record-типи)
    │   │   ├── ProductDto.cs
    │   │   ├── WarehouseDto.cs
    │   │   └── ImportResult.cs
    │   │
    │   └── Import/          # Логіка парсингу та імпорту даних
    │       ├── ProductCsvImporter.cs # Розбір CSV через switch expression та патерни
    │       ├── ProductJsonImporter.cs # Розбір JSON через System.Text.Json
    │       └── MixedCsvImporter.cs    # Розбір поліморфних записів за префіксами
    │
    └── Cli/                 # Консольний застосунок (.NET Console Executable)
        ├── Cli.csproj       # Має ProjectReference на Core
        └── Program.cs       # Демонстрація домену (ЛР4), вибір стратегії імпорту та статистика
```

### Призначення компонентів:

- **`src/Core` (Class Library):**
  * Компілюється у файл `.dll` і не має самостійної точки входу (`Main`).
  * Інкапсулює доменні сутності (`Domain/`), моделі DTO (`Dto/`) та логіку розбору вхідних файлів (`Import/`).
  * Не має залежностей від консолі чи файлової системи у доменній частині, що дозволяє підключати цей проєкт до Web API чи UI.
  * **Правило залежностей:** `Cli` -> `Core` (відсутні циклічні зв'язки).

- **`src/Cli` (Console Application):**
  * Виконуваний модуль (`.exe`), що взаємодіє з користувачем через консоль.
  * Відповідає за демонстрацію доменної моделі, обробку винятків, зчитування аргументів (`args`), перевірку наявності файлів та виведення таблиць і статистики.

## 3. Інструкція зі збірки та запуску

### Збірка всієї системи
```bash
dotnet build
```

### Збірка окремо бібліотеки Core (перевірка multi-targeting)
```bash
dotnet build src/Core/Core.csproj
```

### Сценарії запуску застосунку

```bash
# Демонстрація доменної моделі та інваріантів (ЛР4, за замовчуванням)
dotnet run --project src/Cli

# Явний запуск демонстрації доменної моделі
dotnet run --project src/Cli -- --domain

# Імпорт CSV-файлу з передачею аргументу шляху
dotnet run --project src/Cli -- data/sample.csv

# Імпорт JSON-файлу (автоматичний вибір парсера за розширенням .json)
dotnet run --project src/Cli -- data/sample.json

# Імпорт змішаного CSV-файлу товарів та складів (префікси P і W)
dotnet run --project src/Cli -- data/mixed.csv

# Перегляд системної діагностичної інформації середовища
dotnet run --project src/Cli -- --info
```

## 4. Доменна модель, інваріанти та інкапсуляція (ЛР4)

У межах 4-го тижня створено багату доменну модель (Rich Domain Model) для сутності `Product` (`src/Core/Domain/Product.cs`).

### Особливості архітектури сутності:
- **Інкапсуляція стану:** стан об'єкта захищено приватним полем `_quantity` та властивостями лише для читання (`{ get; }`). Зовнішній код не може довільно змінити залишок.
- **Приватний конструктор і фабрика:** конструктор оголошено як `private`, що унеможливлює створення об'єкта в обхід перевірок. Єдиний спосіб конструювання — статичний фабричний метод `Product.Create(...)`.
- **Контроль змін:** оприбуткування та видача товару виконуються виключно через бізнес-методи `RegisterArrival(amount)` та `Issue(amount)`.
- **Динамічний статус (Enum):** статус запасу `StockStatus` (`OutOfStock`, `LowStock`, `InStock`) обчислюється автоматично через `switch expression` на основі поточного заливочного обсягу.
- **Мапінг DTO:** методи `ToDto()` та `FromDto(dto)` забезпечують зв'язок із форматом даних 3-го тижня. При цьому `FromDto` гарантовано викликає фабрику `Create(...)`, проганяючи відновлені дані через усі доменні перевірки.

### Перелік доменних інваріантів (бізнес-правил)

1. **Обов'язковість ідентифікаторів та текстових полів:**
   * Поля `Id`, `Sku`, `Name` та `Unit` обов'язкові та не можуть бути порожніми або містити лише пробіли.
   * *Тип винятку:* `ArgumentException`.
2. **Невід'ємність початкового залишку:**
   * Початковий залишок товару `quantity` при створенні не може бути меншим за нуль (`< 0`).
   * *Тип винятку:* `ArgumentOutOfRangeException`.
3. **Коректність кількості в операціях:**
   * Кількість оприбуткування чи видачі `amount` має бути суворо більшою за нуль (`> 0`).
   * *Тип винятку:* `ArgumentOutOfRangeException`.
4. **Захист від перевитрати (списання понад залишок):**
   * Кількість видачі `amount` не може перевищувати поточний залишок `_quantity`.
   * *Тип винятку:* `InvalidOperationException`.

## 5. Специфікація форматів вхідних даних та обробка помилок

- **Кодування:** UTF-8 (забезпечує крос-платформну сумісність та коректне відображення кирилиці на Windows, Linux і macOS).
- **Роздільник колонок CSV:** крапка з комою (`;`) — виключає розрив структури при наявності ком у текстових назвах та примітках товарів.
- **Заголовок:** перший рядок таблиці містить назви полів (`id;sku;name;unit;quantity;note`) та автоматично пропускається парсером за правилом `line.StartsWith("id", StringComparison.OrdinalIgnoreCase)`.
- **Культура числових даних:** конвертація чисел виконується із застосуванням `CultureInfo.InvariantCulture`, що гарантує стабільний парсинг незалежно від мовних параметрів ОС.

### Відмовостійкість імпорту:
- Застосунок не падає при виявленні пошкоджених рядків.
- Результат повертається у контейнері `ImportResult<T>`, що містить успішно оброблені записи `Items` та перелік локалізованих повідомлень про помилки `Errors` із точним номером рядка.
- Розбір реалізовано через `switch expression` із патернами властивостей `{ Length: < 5 }`, патернами списків `[_, "", ..]`, охоронними умовами `when` та безпечним `int.TryParse`.

## 6. Дослідження режимів публікації (.NET Publish)

Під час виконання лабораторної роботи досліджено механізми доставки застосунку на цільову платформу Windows x64 (`win-x64`).

### Порівняльна характеристика підходів

- **Self-contained:** публікація пакує ваш код, залежності NuGet та повну копію .NET Runtime під конкретний ідентифікатор платформи (RID). Застосунок повністю автономний і запускається на ПК без встановленого .NET, але має значний розмір.
- **Framework-dependent:** публікація містить лише збірки проєкту. Має мінімальний розмір, але вимагає наявності відповідного встановленого .NET Runtime на машині користувача.
- **Single-File (`PublishSingleFile=true`):** об'єднує всі залежності та бінарники середовища в єдиний монолітний файл `.exe`.
- **Trimming (`PublishTrimmed=true`):** аналізатор видаляє невикористані класи та методи самого фреймворку .NET. Дозволяє критично зменшити розмір автономного файлу, проте потребує обережності при роботі з типами, що використовують рефлексію (наприклад, стандартна серіалізація JSON генерує попередження `IL2026`).

### Результати вимірювань розмірів публікацій (RID: win-x64)

| Режим публікації | Команда розгортання | Розмір каталогу | Кількість файлів | Потрібен .NET Runtime |
| :--- | :--- | :--- | :--- | :--- |
| **Framework-dependent** | `dotnet publish src/Cli -c Release -r win-x64 --self-contained false` | 199 КБ | 7 | Так (.NET 10) |
| **Self-contained** | `dotnet publish src/Cli -c Release -r win-x64 --self-contained true` | 76.6 МБ | 194 | Ні |
| **Single-File** | `... --self-contained true -p:PublishSingleFile=true` | 70.1 МБ | 2 (`.exe`, `.pdb`) | Ні |
| **Trimmed (Single-File)** | `... -p:PublishSingleFile=true -p:PublishTrimmed=true` | 12.5 МБ | 3 | Ні |

### Прямий запуск скомпільованого бінарника

Запуск безпосередньо з каталогу публікації (без утиліти `dotnet run`):

```cmd
# Прямий виклик автономного файлу
.\publish\self-contained\Cli.exe

# Прямий виклик з файлом даних
.\publish\self-contained\Cli.exe ..\..\data\sample.csv
```

## 7. Multi-targeting та умовна компіляція

Бібліотеку `src/Core` налаштовано на збірку під дві версії платформи одночасно за допомогою тегу `<TargetFrameworks>net8.0;net10.0</TargetFrameworks>` у файлі `Core.csproj`.

У коді реалізовано умовну директиву препроцесора:

```csharp
#if NET10_0_OR_GREATER
    private const string CurrentBuildNote = "Збірка під net10.0";
#else
    private const string CurrentBuildNote = "Збірка під net8.0";
#endif
```

При компіляції формуються незалежні бінарні каталоги `bin/Debug/net8.0/` та `bin/Debug/net10.0/`.
